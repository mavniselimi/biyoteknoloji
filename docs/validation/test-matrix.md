### 1.1 What the requirement rows do *not* say

A row saying 975 tests exercise `VER-REQ-003` does not say the requirement
holds. It says 975 tests are claimed to be about it. Whether they passed is a
*result*, and results come from a run - see
`data/verification/wp19-verification-run.json` and the gate status. Keeping the
two apart is what stops "a test exists" being rendered as "the requirement is
met".

### 2.1 The two categories that do not execute everywhere

- **`POSTGRESQL_INTEGRATION`** needs a disposable PostgreSQL reached through
  `TEST_DATABASE_URL`. Without one it reports `BLOCKED` with the exact skipped
  identifiers. A driver is not a database, schema inspection is not a pass, and
  SQLite is not evidence of PostgreSQL behaviour.
- **`BROWSER_E2E`** needs Playwright *and* an installed Chromium. Installing
  the package is not sufficient and the skip message says which of the two is
  missing.

`ASGI_RUNTIME` executes wherever the `api`/`web` extras are installed, and its
result is recorded as evidence rather than inferred from the packages being
importable.

## 5. Skips

Over 90% of the suite is declared `NEVER` - a skip there is unexplained by
definition and fails its profile. The exceptions:

| Suite | Policy | May skip for |
|---|---|---|
| `tests.integration.db.*` | `ENVIRONMENT_DEPENDENCY` | psycopg absent, or no disposable PostgreSQL |
| `tests.integration.web.test_browser_e2e` | `ENVIRONMENT_DEPENDENCY` | Playwright or Chromium absent |
| `tests.integration.api.test_asgi_runtime` | `INVERTED` | the framework *is* installed, so the missing-dependency path cannot be exercised |
| `tests.integration.web.test_asgi_web` | `ENVIRONMENT_DEPENDENCY` | the framework is absent |
| `tests.unit.web.test_client` | `INVERTED` | httpx *is* installed |
| `tests.unit.snapshots.test_snapshot_build` | `CAPABILITY` | the filesystem ignores `chmod` |
| `tests.unit.verification.test_filesystem_capability` | `CAPABILITY` | five named host limitations |
| `tests.unit.verification.test_coverage_and_database` | `INVERTED` | coverage.py *is* installed |

An observed skip is `ALLOWED` only when its reason contains one of the declared
substrings for that suite. "PostgreSQL is missing" does not excuse a browser
test, and a test with no inventory entry gets no benefit of the doubt.

## 6. Reading a row

Each inventory row carries:

| Field | Meaning |
|---|---|
| `suite_id` / `module` | the stable identifier everything else keys on |
| `category` | one of the sixteen |
| `work_package` | who owns the code it exercises |
| `criticality` | whether a failure blocks a release |
| `requirements` | which `VER-REQ-*` it serves |
| `safety_invariants` | which `SAFETY-INV-*` it is mapped to (a map, see §4) |
| `command` | how to run exactly this suite, with no discovery in between |
| `dependencies` | what must be present for it to execute |
| `offline` | whether it needs no network (all of them) |
| `synthetic_fixtures` | whether it builds its inputs rather than reading real data |
| `skip_policy` / `permitted_skip_reasons` | whether it may skip, and for what |
| `evidence` | the artifact or document it backs |
| `assigned_by` | which category rule decided, so "why is this SNAPSHOT" has an answer |
| `test_count` / `test_id_sha256` | how many tests, and a digest over their sorted identifiers |

The identifiers themselves are not listed: five thousand names re-derivable in a
second are bulk rather than evidence, and the digest keeps the property they
were there for - a test added, removed or renamed changes it, so the committed
artifact goes stale and says so. `pgx-verify inventory --by-test` prints them.
