# API runtime records

**This directory holds one file, and a test asserts that it holds no other.**

A record here would mean the API had served real traffic. It has not. No ASGI
server has run against this repository: FastAPI, Pydantic, Starlette, Uvicorn
and HTTPX cannot be installed in the environment WP-16 was built in, no
PostgreSQL service has been started, no release is registered, and the claim
boundary is `DRAFT / AWAITING HUMAN AND SCIENTIFIC REVIEW`. Every one of those
is enough on its own to make a real assessment through the API impossible.

`wp16-real-gate-status.json` is the machine-readable statement of all of that.
It is generated by `apps.api.gate_status.build_gate_status`, which measures
rather than asserts: it imports each package to find out whether it is
importable, walks directories to count fixtures, and regenerates the OpenAPI
document to check the committed artifact against it. Every count in it carries
the source it was read from, so "zero real assessments because there is no
database" is never rendered as the same claim as "zero real assessments
because a query returned none".

Synthetic API fixtures are never written here. They live under
`tests/fixtures/wp16/`, every one of them is labelled synthetic, and no
endpoint returns one: the routers read from the injected provider, and a
deployment that has no provider for a capability answers with the typed
unavailability for that capability rather than with a fixture.
